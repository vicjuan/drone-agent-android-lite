# DJI 黑線循跡：控制迴圈、Profiling 與改進歷程

## 一、目前成果與控制迴圈

DJI Mini 4 Pro 沿直徑約 1.5 公尺的圓形黑膠帶軌跡飛行，最佳實飛紀錄為 **7.9 秒／圈（09/01）**。系統由向下拍攝的相機即時辨識黑膠帶，判斷飛行路徑與方向。

飛行的過程中，機頭大致朝向同一方向，不跟著圓周轉動；飛機透過前進、側移與後退的速度組合，沿著黑膠帶繞圈，彷彿花式滑冰。整個控制迴圈如下：

```text
透過相機取得影像
    ↓
從影像中找出黑膠帶的位置
    ↓
找出膠帶中央的路線，並檢查辨識結果是否可靠
    ↓
判斷接下來要飛向哪裡、路線彎得多急，以及飛機偏離路線多少
    ↓
根據路徑、機頭朝向和實際飛行速度，調整接下來的速度與行進方向
    ↓
將速度與方向指令傳給無人機
    ↓
無人機依照指令移動
    ↓
回到第一步，持續觀察路線並修正飛行
```

## 二、Pseudo-code

**主流程與事件**

```text

機頭偏航角速度命令 = 0
水平命令 = {前進: 0, 側移: 0}
速度命令 = 0
曲率估計值 = 0
飛行資料 = {
    高度: 不可用,
    機頭方向: 不可用,
    水平地速向量: 不可用
}

on DJI回報高度(高度):
    飛行資料.高度 = 高度

on DJI回報姿態(姿態):
    飛行資料.機頭方向 = 姿態.yaw

on DJI回報速度(速度):
    飛行資料.水平地速向量 = {X: 速度.x, Y: 速度.y}

on 收到影像(影像):
    background:
        結果 = 辨識黑膠帶(影像)
        emit 辨識完成(結果)

on 啟動循線:
    上次控制更新時間 = 讀取系統單調時鐘秒數()

function 辨識黑膠帶(影像):
    黑色區域 = 利用OpenCV找出黑色候選區域(影像)
    中央路線 = 利用Zhang–Suen骨架化與路徑搜尋抽出黑色候選區域的連續中心線(黑色區域)
    if 中央路線 == 不可用:
        return 不可用
    if not 符合膠帶形狀與周圍顏色(中央路線, 影像):
        return 不可用
    信心 = 評估路線可靠程度(中央路線, 影像)
    return {中央路線: 中央路線, 信心: 信心}

on 辨識完成(結果):
    if 結果 == 不可用:
        路線 = 不可用
    else:
        路線 = 以PurePursuit計算路線追蹤目標與曲率(結果, 飛行資料)
    沿線速度 = 以速度向量投影計算可用沿線速度(飛行資料, 行進方向)
    更新飛行指令()

every 50 ms:
    更新飛行指令()

function 更新飛行指令():
    if 人工接管 or 降落 or 飛行狀態失效 or 控制權失效 or 機頭資料失效:
        清零命令並停止循線()
        return

    目前時間 = 讀取系統單調時鐘秒數()
    經過時間 = max(0, min(目前時間 - 上次控制更新時間, 0.25))
    上次控制更新時間 = 目前時間
    機頭偏航角速度命令 = 計算機頭偏航角速度命令(飛行資料.機頭方向, 機頭目標)
    if 路線 == 不可用 or 路線資料過舊:
        處理路線暫時不可用(經過時間)
        return

    偏差 = 更新路線偏差估計(路線, 行進方向, 沿線速度)
    if abs(偏差.目標方向差) > 追蹤角度上限:
        清零命令並停止循線()
        return

    目標速度 = 計算目標速度(路線, 沿線速度, 偏差)
    速度命令 = 計算速度命令(速度命令, 目標速度, 偏差.速度上限比例, 經過時間)
    轉向 = 計算本次轉向(行進方向, 沿線速度, 偏差, 經過時間)
    行進方向 = 轉向.方向
    水平命令 = 計算水平命令(路線, 行進方向, 速度命令, 沿線速度, 轉向.速度)

every 25 ms:
    if 仍持有控制權:
        DJI.VirtualStick.發送(水平命令.前進, 水平命令.側移, 機頭偏航角速度命令)
```

**控制計算函式**

以下函式依主流程的使用順序列出；角度使用度，曲率使用弧度／公尺，時間使用秒。

```text
function 計算機頭偏航角速度命令(目前方向, 目標方向):
    方向差 = (目標方向 - 目前方向 + 180) % 360 - 180
    轉動速度 = 方向差 * 機頭修正係數
    return max(-機頭轉速上限, min(機頭轉速上限, 轉動速度))

function 處理路線暫時不可用(經過時間):
    if 持續找不到可用路線的時間 > 等待時間上限:
        清零命令並停止循線()
        return

    曲率估計值 = 0
    橫向偏離估計值 = 0
    if not 仍可短暫保持:
        速度命令 = max(0, 速度命令 - 失路減速度上限 * 經過時間)

    水平命令 = 依方向分解速度(行進方向, 速度命令)

function 更新路線偏差估計(路線, 行進方向, 沿線速度):
    if 沿線速度 == 不可用:
        曲率估計值 = 0
    else:
        本次曲率 = max(-曲率上限, min(曲率上限, 路線.曲率))
        曲率估計值 += 曲率平滑比例 * (本次曲率 - 曲率估計值)

    目標方向差 = (路線.目標方向 - 行進方向 + 180) % 360 - 180

    過彎目標方向差估計值 = 曲率估計值 * 所需前視距離 / 2 * 180 / π
    剩餘方向誤差 = 目標方向差 - 過彎目標方向差估計值

    彎道預期橫向偏移 = abs(曲率估計值) * 所需前視距離 * 所需前視距離 / 2
    有效橫向偏離 = max(0, abs(路線.偏離距離) - 彎道預期橫向偏移)
    方向偏差速度上限比例 = 計算速度上限比例(abs(剩餘方向誤差), 方向不降速門檻, 方向降到零門檻)
    橫向偏離速度上限比例 = 計算速度上限比例(有效橫向偏離, 橫向不降速門檻, 橫向降到零門檻)
    return {
        曲率: 曲率估計值,
        目標方向差: 目標方向差,
        剩餘方向誤差: 剩餘方向誤差,
        速度上限比例: min(方向偏差速度上限比例, 橫向偏離速度上限比例)
    }

function 計算速度上限比例(偏差, 不降速門檻, 降到零門檻):
    比例 = 1 - (偏差 - 不降速門檻) / (降到零門檻 - 不降速門檻)
    return max(0, min(1, 比例))

function 計算目標速度(路線, 沿線速度, 偏差):
    目標速度 = 基準速度命令
    if 沿線速度 != 不可用 and 沿線速度 < 期望沿線速度:
        增加量 = min(期望沿線速度 - 沿線速度, 最大允許增加量)
        目標速度 += 增加量

    if 路線.信心 < 可信門檻:
        信心速度上限 = 低速命令
    else:
        信心速度上限 = 目標速度

    偏差速度上限 = 信心速度上限 * 偏差.速度上限比例
    可見距離比例 = max(0, min(1, 路線.可見前視距離 / 所需前視距離))
    前視速度上限 = 目標速度 * 可見距離比例
    return min(目標速度, 偏差速度上限, 前視速度上限)

function 計算速度命令(目前速度, 目標速度, 偏差速度上限比例, 經過時間):
    允許加減速度 = 加減速度上限
    if 偏差速度上限比例 == 0:
        允許加減速度 = 偏差過大時的減速度上限

    速度差 = 目標速度 - 目前速度
    本次可變速度 = 允許加減速度 * 經過時間
    return 目前速度 + max(-本次可變速度, min(本次可變速度, 速度差))

function 計算本次轉向(目前方向, 沿線速度, 偏差, 經過時間):
    預先轉彎速度 = 0
    if 沿線速度 != 不可用:
        預先轉彎速度 = 沿線速度 * 偏差.曲率 * 180 / π

    轉向速度 = 預先轉彎速度 + 偏差.剩餘方向誤差 * 修正強度
    轉向速度 = max(-轉向速度上限, min(轉向速度上限, 轉向速度))
    if 經過時間 == 0:
        轉向速度 = 0

    新方向 = (目前方向 + 轉向速度 * 經過時間 + 180) % 360 - 180
    return {方向: 新方向, 速度: 轉向速度}

function 計算水平命令(路線, 行進方向, 速度命令, 沿線速度, 轉向速度):
    提前角度 = 0
    if 速度命令 > 0:
        if 轉向速度 > 0: 
            提前角度 = 16
        else if 轉向速度 < 0: 
            提前角度 = -16

    命令方向 = 行進方向 + 提前角度
    沿線命令 = 依方向分解速度(命令方向, 速度命令)
    回正速度 = 更新橫向回正速度(路線.偏離距離, 速度命令, 沿線速度)
    回正方向 = 路線.切線方向 + 提前角度 + 90
    回正命令 = 依方向分解速度(回正方向, 回正速度)
    前進速度 = 沿線命令.前進 + 回正命令.前進
    側移速度 = 沿線命令.側移 + 回正命令.側移
    合成速度 = sqrt(前進速度 ** 2 + 側移速度 ** 2)
    縮放比例 = 1
    if 合成速度 > 最大速度命令:
        縮放比例 = 最大速度命令 / 合成速度

    return {前進: 前進速度 * 縮放比例, 側移: 側移速度 * 縮放比例}

function 更新橫向回正速度(偏離距離, 速度命令, 沿線速度):
    if 沿線速度 == 不可用:
        橫向偏離估計值 = 0

    if 速度命令 == 0:
        回正偏離 = 偏離距離
    else if 沿線速度 == 不可用:
        回正偏離 = 0
    else:
        橫向偏離估計值 += 偏離平滑比例 * (偏離距離 - 橫向偏離估計值)
        回正偏離 = 橫向偏離估計值

    回正速度 = 回正偏離 * 回正強度
    return max(-回正速度上限, min(回正速度上限, 回正速度))

function 依方向分解速度(方向, 速度):
    弧度 = 方向 * π / 180
    return {前進: 速度 * cos(弧度), 側移: 速度 * sin(弧度)}

function 清零命令並停止循線():
    速度命令 = 0
    水平命令 = {前進: 0, 側移: 0}
    機頭偏航角速度命令 = 0
    循線中 = false
```

**量測重點**

- **軟體端到端平均 67.36 ms。** 起點是 App 收到已解碼影格，終點是 MSDK 返回。
- **主要計算成本在影像，不在控制數學。** App 收到影格至辨識完成平均 47.38 ms；中心線抽取平均 15.23 ms，約占候選評分的 87%。控制決策本身只需約 0.15 ms，連同前置判斷與命令更新共 0.22 ms。
- **327.2 ms 目前無法再細分，原因如下**
  - DJI 未提供遙控器傳輸、飛控處理及馬達反應等階段的時間戳。 
  - Mini 4 Pro 內部飛行紀錄採非公開格式，且可能包含加密內容。 
  - 現有開源工具無法解析出可與手機時間精確對齊的內部資料。 

## 四、控制迴圈的改進歷程

**1. 建立第一版視覺閉環，首次以 210 秒完成圓形一圈。（08/17–18）**
- 以黑線角度控制偏航、中心偏移控制橫移，兩者對正後才低速前進；先完成直線往返，再將圓形與直線終點判斷分離，避免繞圈途中誤觸 180° 回頭。
- 確認控制權借還與機身座標，建立 Flight Log，讓每次異常能區分是「未送命令」或「送出後未產生預期動作」。

**2. 改用前視導引與方向無關中心線，完成曲線、S 型與約 150 秒的圓形單圈。（08/19–20）**
- 我請 AI 上網搜尋業界技術跟現有成熟論文，尋找更適合連續過彎的循跡方法，減少反覆停下對正，為提高飛行速度建立基礎。
- 最後採用 Pure Pursuit 技術，在前方路徑選取目標，不再只追當下線條角度；骨架中心線取代逐列／逐欄特例，讓水平、斜向與彎道共用一套辨識。
- 保存原始影格與中間遮罩供離線重播，讓反光、接縫與陰影問題可以反覆重現，不必每次重新起飛。

**3. 依路徑條件動態調速，圈時由 64.6 秒降至 34 秒。（08/21）**
- 我請 AI 構思如何在保持循跡穩定的前提下加速，將單圈時間壓到 60 秒內。
- 最後決定不再全程使用同一保守速度；前方平順、可見距離足夠且辨識可信時加速，彎度增加或偏航能力不足時減速。影像與控制節奏提高至約 10 Hz。
- 真機實驗上午達到 **64.6 秒／圈、下午達到107 秒兩圈（平均 53.5 秒）、約 34 秒／圈**。

**4. 加入目標與偏移預測，機頭隨彎道轉向的模式達到約 13 秒單圈。（08/24）**
- 我請 AI 分析提速後轉彎跟不上的原因，構思能減少方向落後與偏離、繼續縮短圈時的方法。
- 最後決定提高可用前進速度、偏航速度與加速度；依連續影格的目標移動補償控制延遲，減少轉彎落後。同時預測橫向偏移，在飛機接近路徑邊緣前減速，而不是偏離後才急停。

**5. 改為固定機頭滑行，降低繞彎對偏航速度的依賴。（08/25–26）**
- 原有的飛行方式陷入瓶頸，我請 AI 重新思考飛行方式，評估能否減少對機頭轉向速度的依賴，突破繞彎時的速度限制。
- 機頭保持不變，以前後／左右速度合成沿線運動；08/25 完成約 **13 秒單圈**，08/26 最後兩圈平均約 **11.5 秒**。

**6. 用 Profiling 找出等待與重複工作，後續最佳單圈進入 9.5 秒。（08/27–28）**
- 我請 AI 用量測找出提速瓶頸，分析哪些影像運算與排程等待可以縮短，而不只是調高速度參數。
- 量測顯示時間主要花在影像與排程。因此我們決定改用候選局部區域處理、重用 OpenCV 緩衝，並讓新影格立即觸發控制，不必等下一個週期。

**7. 補償方向延遲並減少命令等待，最佳單圈由 8.5 秒推進至 7.9 秒。（08/31–09/01）**
- 我請 AI 對照實飛紀錄與指令時序，構思如何減少轉向落後、短暫失路及命令等待，讓高速繞行更連續。
- 加入速度方向相位超前，以及利用前一條中心線與本幀影像延續短缺口的機制，減少方向落後與重新抓線。
- Virtual Stick 由 20 提高至 40 Hz。09/01 最佳單圈為 **7.9 秒**。

**8. 消除中心線查詢與抽取的熱點，改善反應時間與長尾。（09/01–03）**
- 我請 AI 根據 Profiling 找出中心線處理的耗時熱點，構思在維持辨識結果下減少重複計算與延遲的方法。

# 基於 Profiling 的效能改善可行性分析

> 目的：根據現有量測，分析可行的改善途徑及理論效益。

## Profiling 關鍵資訊

| 項目 | 量測結果 |
|---|---:|
| OpenCV 偵測 | 77.9 ms |
| 等待控制器算出命令 | 59 ms |
| 等待搖桿幀送出 | 25 ms |
| MSDK、飛控與機體反應 | 380 ms |
| **端到端合計** | **542 ms** |

- 目前 14 圈平均 **12.43 秒/圈**，平均地速 **0.340 m/s**。
- 低於 11 秒需要至少 **0.385 m/s**，比目前提高約 **13%**。
- 56.2% 的追蹤時間位於漏檢後 1.5 秒內；乾淨時段平均指令速度 0.709 m/s，完整區段平均為 0.584 m/s，相差約 **21%**。

## 第二輪量測如何決定優化

第一輪的 77.9、59 與 380 ms 都是大區段，尚不足以判定應修改哪一段程式。App 已補上細分時間點，下一次相同路線實飛後依下表決策：

| 若主要耗時落在 | 優先驗證的改善 |
|---|---|
| OpenCV 前處理或 cleanup | 重用每幀建立／釋放的 Mat 與 morphology kernel |
| Lab、陰影與地板 flood fill | 在已有可信路徑時縮小處理 ROI；失去路徑立即回到全畫面 |
| morphology 或 contours | 以 ROI 降低處理像素與候選輪廓數 |
| 候選與中心線評分 | 強化便宜的前置 gate，減少昂貴中心線計算次數 |
| UI 排隊或等待固定 tick | 讓新偵測結果直接觸發一次控制更新 |
| 命令等待 20 Hz 搖桿幀 | 對齊控制更新與搖桿發送排程 |

以上是依量測結果選用的方案，不會在尚未知道瓶頸前改動偵測行為。

## 改善途徑與理論可行性

| 優先 | 改善途徑 | Profiling 依據 | 理論效益 | 可行性 |
|---:|---|---|---|---|
| 1 | 減少漏檢後反覆降速 | 受漏檢影響時段占 56.2%；乾淨時段指令速度高約 21% | 低於 11 秒只需約 13% 地速提升；若能回收大部分降速損失，理論上已有足夠空間 | **高** |
| 2 | 縮短偵測完成至控制命令更新 | 第一輪此區段平均 59 ms；第二輪已拆成 detector 回呼、UI 排隊、控制 tick、控制器計算及安全判斷 | 若主要耗時確為固定 tick，可改由新偵測觸發控制，最多回收接近 59 ms | **待第二輪確認** |
| 3 | 降低 OpenCV 每幀成本 | 第一輪整包平均 77.9 ms；第二輪已拆成前處理、分割、地板、形態學、輪廓、候選及 cleanup | 找出占比最高者後，重用 Mat／kernel 或採可信路徑 ROI；若降至 50 ms，約節省 28 ms | **待第二輪確認** |
| 4 | 對齊控制計算與 20 Hz 搖桿發送 | 第一輪平均等待 25 ms；新 trace 直接記錄 `commandToFrameMs` | 最多回收約 25 ms，不必提高 DJI 發送頻率 | **中** |
| 5 | 依速度動態增加前瞻距離 | 命令至地速遙測反映約 380 ms，但包含上／下行傳輸、飛控、物理反應與遙測取樣 | 0.90／1.25 m/s 在整體 542 ms 內分別前進約 0.49／0.68 m；前瞻至少應涵蓋反應距離 | **有條件**：先以第二輪縮小 380 ms 的估計誤差 |

## AI 分析結論

**低於 11 秒在理論上可行，但目前還不能由大區段耗時直接指定程式優化。** 所需平均地速只比目前高約 13%；第二輪 profiling 的目的，是確認應先回收 OpenCV、控制排程還是搖桿排程的哪一段時間。

建議依序處理：

1. 降低漏檢與反覆降速；
2. 移除控制 tick 等待；
3. 以 ROI 降低 OpenCV 耗時；
4. 對齊搖桿發送排程；
5. 最後才提高速度上限。

命令至地速遙測反映約 380 ms，目前只能再分出 App 可觀測的搖桿等待、MSDK 呼叫與遙測 callback 間隔。Mini 4 Pro 雖可透過 DJI Assistant 2 匯出飛行器紀錄，但沒有公開的欄位格式與時鐘定義；除非 DJI Support 提供解析結果，專案無法自行用它拆分飛控、傳輸與機體反應。目前可獨立執行的下一步是同步高速攝影。所有效益仍須由下一次相同路線實飛驗證。
